# CIPC LabEquip Hub 使用指南

## 登录

账号由管理员创建，系统没有注册入口。预置账号以 `123456` 作为首次密码；首次登录必须设置 8-128 位、同时包含字母和数字的新密码。使用完毕请退出，不要只关闭浏览器标签页。

## 角色

| 角色 | 可用范围 |
| --- | --- |
| member | 设备、设备预约、会议室预约、维修保养、采购 |
| admin | member 的全部范围，以及成员管理和设备强制删除 |
| developer | 开发与验收；可切换三种界面视图，并具备设备强制删除能力 |

developer 的视图切换只影响界面展示，不改变该账号的服务端身份；切换到普通用户视图后，服务端仍按 developer 的真实权限校验。admin 可管理成员；admin 和 developer 均可在处理错误数据时强制删除含历史记录的设备。其他日常业务页面与 member 相同。

## 设备与预约

在设备台账中可按关键词、实验室和设备状态组合筛选，并按最近更新、最早录入或设备名称排序。“导出清单”会将当前筛选结果下载为 CSV，便于在 Excel 中继续整理。发起预约时填写设备、日期、起止时间、人数和用途。开始时间必须晚于当前时间；预约提交后直接生效，没有待审批、批准或驳回步骤。

台账顶部四项统计分别表示已录入设备总数、当前可预约设备数、维修中设备数，以及已有设备登记的实验室数量。系统当前以每条台账记录代表一台设备，不使用额外的设备实例层。

同一设备的有效预约不可重叠；相邻时段可首尾相接。维修、停用或报废的设备不能预约。出现冲突时，返回预约日历选择空闲时段后重新提交。系统按时间自动显示“未开始”“使用中”“已完成”，无需人工更新；预约开始前可由预约人取消，开始后不能取消。

点击设备行右侧的更多按钮打开详情。使用“编辑信息”可修改设备名称、资产编号、性能指标、所在实验室和保管人；使用“设备状态”可单独切换为可用、维修中、已停用或已报废。预约不是设备的固定状态，具体占用时段统一以预约日历为准。保存后台账、筛选统计和预约选项会立即更新；维修中、已停用、已报废不会接受新的预约，但既有预约和业务历史仍会保留。

设备详情提供“移除设备”操作。所有登录用户都可移除尚无预约、维修保养或采购历史的误录设备。存在历史记录时，普通用户的删除会被阻止；管理员和开发者会看到预约、维修保养、采购记录的准确数量，经第二次确认后可强制删除设备及全部关联记录。若确认期间记录数量发生变化，系统会中止删除并要求重新核对。强制删除不可恢复，只应用于确认需要整体清除的错误数据，并应先完成数据库备份。

预约日历提供三种互补视图：“周概览”汇总当前一周每天的预约数量、资源类型和主要预约；“月视图”使用固定 42 格展示整月密度和每天前三项摘要，选择日期后会显示当天全部预约；“单项资源”可按名称或编号搜索设备与会议室，只查看所选资源的完整周排期。周、月视图中的预约条目以及设备详情中的“查看日历”均可直接进入对应资源日历。

管理员和开发者可在“会议室预约”页面新增或编辑会议室，包括名称、编号、容量、位置和开放状态。会议室仍有尚未结束的预约时，系统会阻止停用并提示需要处理的预约数量。

“操作审计”支持关键词、对象类型和日期范围筛选，结果按页加载。管理员和开发者可将当前筛选条件下的完整结果导出为 CSV。

“我的预约”只汇总当前登录账号创建的设备与会议室预约。可按未开始、使用中、已完成和已取消筛选；未开始的预约可直接取消，也可从记录进入对应资源所在周的单项日历。页面中的生命周期状态与总览、会议室列表和预约日历使用同一套时间判断。

## 会议室预约

member、admin 和 developer 均可使用“会议室预约”。选择会议室、日期、起止时间、使用人数和用途后提交，预约会立即生效，没有待审批步骤。

- 使用人数必须至少为 1 人，并符合所选会议室的预约要求。
- 同一会议室的有效预约不可在时间上重叠；相邻时段可首尾相接。
- 仅可预约当前可用的会议室，不能选择过去日期。
- 不能提交开始时间已经过去的当天预约。
- 预约人可取消自己尚未开始的会议室预约；developer 可在验收和维护时取消任意尚未开始的会议室预约。

会议室列表、预约列表、新建和取消均通过共享 API 完成，因此刷新或在其他登录设备上访问时会看到相同的排期。

## 维修保养与采购

member 可访问维修保养与采购视图。选择关联设备后，可新增维修或保养类型、处理状态、日期、费用和说明；采购记录可填写供应商、日期、金额、验收状态与备注，并在列表中继续更新验收结果。采购金额只汇总“已验收”记录，待验收和验收未通过记录不会计入。保存后数据会立即进入共享列表。管理员不因角色获得额外的设备、预约、维修或采购权限。

新增“待处理”或“处理中”的维修保养记录后，关联设备会自动进入“维修中”并停止接受新预约。可在记录列表右侧直接更新处理状态；当该设备全部维修保养记录均为“已完成”时，设备自动恢复“可用”。已停用或已报废设备不会被这一联动自动恢复。

## 成员管理与密码重置

admin 可在“成员管理”中创建、编辑和维护成员账号。创建账号后，初始密码为 `123456` 并要求首次改密。

重置密码时，系统生成随机临时密码，注销目标账号已有会话，并要求其下次登录后修改密码。临时密码只在重置结果中显示一次，应通过受控渠道单独交付。管理员应使用正常改密流程修改自己的密码。

所有已登录用户都可点击侧边栏账号旁的“修改密码”按钮，自助输入当前密码和新密码。修改成功后当前会话继续有效，其他登录会话立即失效。

## 操作审计

系统对设备新增、编辑、删除与强制删除，成员创建、编辑与密码重置，预约创建与取消，维修保养和采购记录的创建与状态更新，以及本人修改密码等关键操作写入审计记录。审计与业务变更在同一数据库事务中完成；业务写入失败时不会留下成功记录。

admin 和 developer 可从“操作审计”查看全部成员的关键操作。member 的服务端访问范围只包含本人作为操作者的记录。审计仅保存业务摘要和操作者快照，不保存密码、密码哈希、会话令牌或重置产生的临时密码。developer 切换模拟视图不会改变服务端审计权限。

## 键盘与表单操作

- 使用 Tab 可移动到所有主要操作，当前焦点会显示清晰边框。
- 页面最前方提供“跳至主内容”入口，键盘聚焦后可见。
- 弹窗和设备详情打开后，焦点会进入当前区域；Tab 不会跳到背景页面，Escape 可关闭并返回原操作位置。
- 预约结束时间早于开始时间或预约开始时间已过去时，表单会在时间字段附近直接显示错误。
- 连续输入搜索词时，列表会在短暂停顿后刷新，减少界面抖动。

## 常见问题

**登录后只能看到改密页面？** 账号仍使用初始或临时密码，完成改密后即可进入业务页面。

**页面无法加载数据？** 确认 Web 与 API 均已启动；前端不会回退到浏览器本地业务数据。

**忘记密码？** 联系管理员执行成员密码重置。

## 维护

```bash
pnpm dev
pnpm check
pnpm backup:db --data apps/api/data/development.sqlite --output-dir apps/api/data/backups
```

备份脚本只有在快照通过 SQLite 完整性检查后才返回成功。备份与恢复必须遵循 [VPS 部署说明](../deploy/vps/README.md)，不要直接复制 WAL 模式下的单独数据库主文件。
