# 实验室资源平台 v1.4.12 发布说明

发布日期：2026-09-19。状态：正式发布到公开部署仓库；公网生产仍保持 `v1.4.11`，需单独执行升级。

## 本版重点

v1.4.12 在 v1.4.11 的同源交互式使用指南和 Safari/WebKit 修复基础上，补充“新增设备”手把手教程，并集中修复升级、认证、代理和预约状态链路中的稳定性问题。正式数据库结构保持兼容，不要求迁移脚本。

### 新增设备交互式教程

- 普通用户、系统管理员和开发者均可看到“新增设备”教程，与现有设备台账权限一致。
- 教程复用正式的“新增设备”按钮和表单，覆盖设备名称、资产编号、性能指标、所在实验室、设备保管人和初始状态。
- 覆盖必填字段、长度、重复编号、停用实验室和状态选择等虚拟校验，并在保存后使用正式台账列表核对新设备。
- 教程继续使用内存演示适配器，不创建真实设备、预约、账号、备份或升级任务。

### 稳定性与安全修复

- 登录、改密和会话签发在异步校验完成后重新确认凭据与账号状态，避免并发重置或禁用导致旧认证结果被接受。
- 改密使用比较并交换语义，避免两个并发请求覆盖彼此的凭据变更。
- 升级请求增加跨进程 admission 锁和 request 文件保护，避免多个 API/升级代理在网络等待期间互相覆盖任务。
- 升级��理统一 flock、显式使用服务 UID/GID、支持 archive release，并在停止服务、切换 release、健康检查失败时执行补偿和回滚。
- 预约设备/会议室列表、总数和状态映射共用同一有效时间点，边界时刻不会出现分页总数与列表不一致。
- 反向代理只信任受配置的 loopback 代理来源，避免外部伪造转发头改变客户端地址。
- 修复注销失败后的持久重试、迟到响应恢复旧会话、写入成功后审计/派生刷新失败误报，以及预约类型切换等前端竞态。
- 更新局域网/VPS Nginx 与 systemd 升级单元模板，包含 `--flock-held`，避免新旧锁重复导致升级任务误判繁忙。

## 兼容性与升级前检查

- 兼容 v1.3.0 及之后的生产数据库；本版没有强制数据库迁移。
- 升级前必须创建包含 WAL 的 SQLite 一致性快照，并保留当前 release 以便代码回滚。
- 公开仓库只包含代码、配置模板和文档，不包含生产数据库、备份、真实账号或服务器凭据。
- 生产切换前请同步新的升级 systemd 单元和 Nginx 模板，并在宿主机验证 API、Web、数据库和升级状态。

## 验证结果

- Node 测试：`227` 项，其中 `224` 通过、`3` 项 Linux 专项在 macOS 开发机跳过、`0` 失败。
- 通过全部变更文件的 Node 语法检查、Shell 语法检查和 `git diff --check`。
- WebKit/Chromium 教程回归覆盖十项课程、自动演示、暂停/继续、移动端和新增设备流程；业务请求保持在内存适配器内。
- Linux 专项包括真实用户身份降权、跨入口 flock 串行化和旧 unit 兼容性，需在 Ubuntu 部署机上再跑一次。

## 快速升级与回滚

学校已部署环境请参阅 [发布、迁移与部署流程](RELEASE_AND_MIGRATION.md#upgrade-v1-4-12)。升级代理会先备份、测试候选 release、切换并健康检查；失败时恢复上一代码 release。数据库恢复仍需管理员依据备份快照单独执行，不能把代码回滚当作数据回滚。
